# V01 动态单人视觉检测

在已有 WSL ROS2 Humble 环境中，从视觉原型目录启动。默认打开 Gazebo 窗口，以及原始 RGB 和 YOLO 标注两路 `rqt_image_view` 窗口。Gazebo 提供预设观察视角，三个窗口可以手动平铺或调整大小。终端显示场景阶段和对应的仿真时间，Gazebo 状态栏显示绝对仿真时间。

```bash
cd ~/ros2_ws/src/my_dwa_controller/visual_prototype
./run_v01_gui.sh A    # 机器人静止，行人横移
./run_v01_gui.sh B    # 行人静止，机器人直行经过
./run_v01_gui.sh C    # 机器人直行，行人横穿
./run_v01_gui.sh --help
```

首次部署先按 [原型 README](README.md) 准备 Waffle、3DGEMS 模型、YOLO 权重和 Python 环境。第一次启动会用现有 CMake、C++ 编译器及 Gazebo Classic 开发头文件，在 `.cache/v01-gazebo-build/` 编译 V01 位姿插件。启动脚本复用 `prototype.launch.py`，沿用原有 YOLOv8n、CUDA、`conf=0.25` 和 `imgsz=640`。`--no-viewers` 只打开 Gazebo，`--headless` 跳过窗口并保留检测和日志。WSL 中的相机渲染仍需可用的图形环境。

## 运动参数与预期时间线

复制 [v01_modes.json](v01_modes.json) 后可用 `./run_v01_gui.sh C --config /路径/配置.json` 载入。初始位置用米，朝向用弧度，启动延迟、运动持续时间及末尾等待均用仿真秒。机器人速度为机器人本体 x 方向速度，经 `/cmd_vel` 发送。行人速度是 Gazebo 世界坐标下的 `vx_mps` 和 `vy_mps`。默认行人模型朝向保持固定。

| 模式 | 机器人 | 行人 | 预期结束 |
| --- | --- | --- | ---: |
| A | 原地静止 | 从 `(2.069, -0.497)` m 起，2.0 s 开始沿 +y 以 0.25 m/s 移动 3.6 s，横移 0.90 m | 7.60 s |
| B | 从原点起，2.0 s 开始沿 +x 以 0.35 m/s 直行 9.0 s | 固定于 `(2.4, -0.75)` m | 13.00 s |
| C | 从原点起，2.75 s 开始沿 +x 以 0.28 m/s 直行 8.0 s | 从 `(2.25, -0.90)` m 起，2.0 s 开始沿 +y 以 0.42 m/s 移动 4.3 s | 12.75 s |

每次只生成一个行人。B 通过横向错位保持间距，C 通过启动时序让行人先横穿机器人前方。时间线从控制接口就绪且收到首个新检测输出后的下一条 `/clock` 样本起算。该输出只用于启动就绪，检测内容和真值均不参与运动控制。轨迹由 `/clock` 样本推进，行人结束事件等待 Gazebo 确认最后一次位姿命令。上游位姿服务会临时改变世界暂停状态。V01 插件在 Gazebo 更新线程应用位姿并回复，暂停时保留待应用的命令，直到恢复。 [Gazebo ROS 状态插件源码](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/3.9.0/gazebo_ros/src/gazebo_ros_state.cpp#L260-L275)

## 暂停、继续、重置与结束

Gazebo 底部播放控件可暂停和继续。也可在第二个 WSL 终端使用脚本打印的当前运行目录。下列命令只访问本次运行的本机 ROS 域。

```bash
source /实际运行目录/ros_env.sh
ros2 service call /pause_physics std_srvs/srv/Empty '{}'
ros2 service call /unpause_physics std_srvs/srv/Empty '{}'
ros2 service call /reset_simulation std_srvs/srv/Empty '{}'
```

暂停期间，机器人、行人和场景计时一起冻结。使用 `/reset_simulation` 重置仿真时间。控制节点在看到时钟倒退后发送零速度，等待轮速衰减并恢复两个实体初始位姿，并在同一目录中用新的 `epoch` 从 0 s 重新记录。若在暂停时重置，继续播放后等到新的时钟样本即可。需要完全独立的记录时，在原启动终端按 **Ctrl+C**，再执行同一个启动命令。

`Scenario completed` 后 Gazebo 和图像窗口留在屏幕上，便于检查终态。Ctrl+C 关闭这次启动管理的 Gazebo、状态发布器、场景控制、YOLO 和查看器。

## 查看图像和输出

启动时若缺少 `rqt_image_view`，可从另一个终端载入当前运行的 `ros_env.sh`，再使用已安装的 `image_tools`。两个命令分别在两个终端运行。

```bash
ros2 run image_tools showimage --ros-args \
  -r image:=/visual_prototype/camera/image_raw -p reliability:=best_effort -p use_sim_time:=true
ros2 run image_tools showimage --ros-args \
  -r image:=/visual_prototype/annotated -p reliability:=best_effort -p use_sim_time:=true
```

检测输出为 `/visual_prototype/detections`，帧级 JSON 指标为 `/visual_prototype/metrics`。相机内参在 `/visual_prototype/camera/camera_info`，光学帧为 `camera_rgb_optical_frame`。启动脚本检查本机 DDS 端口并锁定可用 ROS 域及对应的 Gazebo master 端口，图形配置和日志保存于本次目录。

| 每次运行的文件 | 内容 |
| --- | --- |
| `config.json`、`v01.world` | 生效的模式、运动参数和初始场景 |
| `timeline.jsonl` | 事件名、计划时间、实际相对秒数、绝对 `/clock` 时间戳和 epoch |
| `detections.jsonl` | 原有 YOLO JSON，附 epoch 与相对时间。保留原始图像时间戳、bbox、置信度和耗时 |
| `statistics.jsonl` | 每个 epoch 的状态、输出帧数、平均前向与 predict 耗时、墙钟与仿真输出频率 |
| `ground_truth.jsonl` | 分别通过 Gazebo 查询两个实体，保存服务返回的仿真时间、世界位姿、速度和位置差分速度 |
| `launch.log`、`ros/` | 启动配置、终端阶段日志、各节点输出及退出状态 |

墙钟仅用于计算吞吐量。暂停会计入墙钟统计区间，因此复盘暂停实验时优先看仿真 Hz。行人以静态视觉实体逐次设位姿，Gazebo 自带的 twist 通常为零，实际平移可用 `pose_delta_linear_mps` 或位姿序列查看。

## 2026-11-12 GUI 实测

在 WSL Ubuntu 22.04、ROS2 Humble、Gazebo Classic 11.10.2 上用默认 GUI 启动逐一完成。YOLO 在 RTX 4070 Laptop GPU 上推理，Gazebo 使用 WSLg 软件渲染。两路查看器、相机、Gazebo 插件、状态发布器、YOLO、V01 位姿插件和场景节点共 11 个 ROS 节点，逐个查询均为 `use_sim_time=true`。

### 已知限制

- 行人沿固定朝向平移，使用视觉模型的位姿控制。默认路线通过几何间距避免接触，尚未验证带物理行人碰撞体、不同起点或自定义速度组合。
- 验收期间曾观察到 Gazebo Classic 的 `gzclient` 在 SIGINT 退出阶段报 `-11`。检查了本次启动的进程，均已退出。
- 检测记录覆盖场景有效时间。暂停、渲染速度和 DDS 到达顺序会影响墙钟输出率。本轮使用固定光照、单人和仿真相机，未做真实机器人或正式导航共运行测试。
